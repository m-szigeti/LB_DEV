More Information

This page describes the Lebanon vulnerability mapping tool: what it shows, how to use the main features, and how composite theme scores and the Overall Vulnerability Index are calculated.

The tool provides a structural vulnerability baseline for exploration and reporting. It is not a real-time early-warning system. Interpret results alongside local knowledge and other data sources. Scores are comparable within the selected administrative resolution only (cadastre, district, or governorate).

What the Tool Shows

The map displays composite vulnerability and tension indexes across Lebanon, plus contextual layers that are not part of the composite calculation. Composite scores use a 0–1 scale. In the published Overall Vulnerability Index, higher scores indicate lower vulnerability / greater resilience, and lower scores indicate higher vulnerability.

Sidebar sections

  1. Composite Indexes — Overall Vulnerability Index and theme pillars (with optional sub-indicators).
  2. Stressors — Contextual layers such as road access, collective shelters, TTF hotspots, and population.
  3. UNDP Intervention Mapping — Project locations clustered by type of activity.

Administrative resolution

Use Cadastre, District, or Governorate to change the map unit. Changing resolution reloads the matching GeoJSON layers. Not every theme is available at every resolution (for example, some themes are unavailable at cadastre).

How to Use the Tool

Basic workflow

  1. Pick a resolution in the left panel (Cadastre / District / Governorate).
  2. Turn on a theme under Composite Indexes (Overall and/or one or more pillars).
  3. Click a polygon to open a popup with the unit’s score, population context, and theme bars.
  4. Explore sub-indicators with the chips under each pillar to map a single input instead of the composite.
  5. Add context from Stressors or UNDP Intervention Mapping as needed.

Analysis and display features

  • Active Layers — Rankings, indicator definitions, and layer details for what is currently on.
  • Analysis (AOI) — Select map units (or whole districts at cadastre), review summary statistics, export CSV / PDF briefing, and design a custom index for the selected area.
  • Color (per composite layer) — Show that layer alone as a plain choropleth.
  • Show Labels — Place score labels on the map.
  • Advanced Options — Basemap, global color-only mode, and class-limit method (equal count, equal interval, natural breaks).
  • Build custom index — Choose themes and sub-indicators; the tool recalculates a custom overall using the official scoring recipe. Export a Before/After comparison PNG when available.

Composite Indexes

Theme layers summarise groups of indicators into a single score per administrative unit. The Overall Vulnerability Index is a second-stage composite built from theme-level inputs.

How Composite Scores Are Calculated

Theme composites and the Overall Vulnerability Index follow the same statistical recipe (implemented in the data pipeline and mirrored in the tool for custom / experimental recomputation).

Official scoring recipe

  1. Numeric coercion
    Indicator values are converted to numbers (including binary-aware handling of yes/no style fields).
  2. Median imputation
    Missing values in each indicator are filled with that indicator’s median across units at the current resolution.
  3. Min–max normalisation
    Each indicator is scaled to 0–1 using the observed minimum and maximum among units at that resolution. Selected indicators that run in the opposite direction (for example night-time lights) are inverted so that higher normalised values align with the intended vulnerability direction for scoring.
  4. Kendall τ weights
    A Kendall τ correlation matrix is computed between the normalised indicators. Each indicator’s weight is proportional to its mean absolute Kendall τ with all other indicators. Weights are rescaled to sum to 1. If correlations are undefined or all near zero, equal weights are used.
  5. Weighted sum
    The composite score for each unit is the weighted sum of its normalised indicator values (typically stored as composite_score for themes, or overall_vulnerability_score for Overall).

Theme composites vs Overall

Theme / pillar scores

Most themes apply the recipe above to that theme’s sub-indicators. Displacement Pressure and Demographic Tension / Stress often enter the Overall stage as a single official metric (for example Displacement Ratio or Demographic Factor), rather than a Kendall sub-composite of every listed input—unless a custom build recomputes from selected sub-indicators.

Overall Vulnerability Index

Overall is a second-stage composite: theme-level scores are joined for each unit, then the same Kendall recipe is applied to those pillar inputs. A weak pillar therefore reduces the overall score. The map shows precomputed Overall scores from the published GeoJSON by default.

Important interpretation notes

  • Resolution matters. Min–max bounds and Kendall weights are computed within the units of the selected resolution. Do not compare a cadastre score directly to a district score.
  • Map colours ≠ raw score formula. Class Limits (equal count, equal interval, natural breaks) only change how scores are binned for the choropleth legend; they do not recalculate the underlying composite.
  • Custom Overall / AOI custom index. These tools re-run the official recipe on the themes (and optional sub-indicators) you select. In AOI mode, normalisation and Kendall weights are computed over the selected units only; units outside the AOI are muted on the map.
  • Weight sandbox. Experimental per-theme sliders keep the same normalisation path but replace Kendall weights with user-chosen weights.

Context Layers (Not Part of the Composite)

Stressors

Road Access Status, Collective Shelter Status, TTF Hotspots, and Population provide operational and demographic context. They can be viewed together with composite layers but are not inputs to the Overall Vulnerability Index formula.

UNDP Intervention Mapping

Project points are clustered by Type of Activity. Popups summarise individual projects; cluster popups show the activity mix nearby. This layer supports situational awareness and does not enter composite scoring.

Frequently Asked Questions

Why do scores change when I switch Cadastre / District / Governorate?

Each resolution uses its own geometry and score table. Normalisation and (for recomputed indexes) Kendall weights are defined among units at that level, so values are not interchangeable across resolutions.

Does Class Limits change the composite calculation?

No. Class Limits only change how continuous scores are grouped into legend colours on the map.

What does AOI Analysis measure?

Area-of-interest summaries aggregate scores already present on the active layers for the selected units (means, class shares, theme contribution, extremes). That is different from designing a custom index, which recalculates a new composite over the selection.

Can I treat the custom or sandbox map as official?

No. Custom Overall, AOI custom index, and the weight sandbox are exploratory. The published Overall and theme GeoJSON remain the reference layers unless your team formally adopts a new build.

How should I communicate results?

Prefer relative language within one resolution (“higher / lower than neighbouring districts”), state the date and layer used, and avoid implying real-time risk or precision beyond what the indicators support.
